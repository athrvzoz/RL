05DDPG maths, step by step

Three updates every step: the critic (Bellman, like Q-learning), the actor (chain rule), the targets (a weighted average). All numbers verified by hand_examples.py.

① The critic: Bellman, exactly as in Q-learning

y   =   r   +   γ · (1 − done) ·  Qtarget( s2 ,  μtarget(s2) )
▲       ▲       ▲   ▲               ▲                 ▲
TARGET  GIVEN   0.99 0 for          slow copy of      slow copy of the actor: its torque in s2
a number by the     Pendulum:       the critic,       REPLACES "max over actions"
        world       never ends      only READ

critic loss  =  average over the 128 rows of  ( Q(s, a) − y )²     ← gradient descent shrinks it

Compare with your Q-learning line target = r + γ · max Q[s2]. The only change: "max over all actions in s2" became "the torque the (target) actor would choose in s2". That's fine because the actor is trained to choose the torque with the highest Q, so μ(s2) ≈ argmax.

Worked example 1: one critic target (by hand)

Row from the buffer:  s, a, r = −0.5, s2           (Pendulum: never terminated, so done = 0)
Target actor in s2:   μtarget(s2) = some torque, and target critic says Qtarget(s2, that torque) = −20.0
TARGET    y = −0.5 + 0.99 × (−20.0) = −20.30
Critic now says Q(s, a) = −18.0
ERROR     y − Q = −20.30 − (−18.0) = −2.30         critic was too optimistic
LOSS      (−2.30)² = 5.29                         gradient descent lowers Q(s, a) toward −20.30
Which state is updated? (same answer as Q-learning)

The critic's weights change so that Q(s, a), the state you left with the torque you actually used (stored in the row), moves toward y. s2 is only read, through the slow target networks. And the row's torque a may be an old, noisy one: that's fine, Bellman holds for any action. That's what makes it off-policy.

How can s2 "know the future"? Bootstrapping, again

Qtarget(s2, ·) is the critic's current guess of everything after s2. At the start it is rubbish (our critic said 0.1 when the truth was −455). Each update copies a little real reward r into the guesses, and the knowledge spreads backwards through the 100,000 rows, just as the goal's value rippled back one square per game on FrozenLake. A network spreads it faster, because nudging one state also nudges similar states.

② The actor: climb the critic's hill (the chain rule)

The actor wants μ(s) to be the torque with the biggest Q. So it changes its weights θ to make Q(s, μ(s)) bigger. How does Q change when one weight θ changes? θ changes the torque a, and the torque changes Q. A chain of two links, so school's chain rule:

 ∂Q        ∂Q        ∂a
────  =  ────  ×  ────            θ ← θ + learning rate × ∂Q/∂θ      (gradient ASCENT)
 ∂θ        ∂a        ∂θ
 ▲          ▲         ▲
 how Q      slope of  how the torque moves when
 reacts     the       you change this weight
 to θ       critic's  (comes from the actor network)
            hill

In code we write actor_loss = −Q(s, μ(s)).mean() and call backward(); PyTorch applies the chain rule through every layer for us. Minimising −Q is the same as maximising Q.

Worked example 2: a one-weight actor (by hand)

Toy actor a = θ · s. Toy critic (one hill) Q(s, a) = 5 − (a − 2s)², best torque = 2s. State s = 1, start θ = 0.5, learning rate 0.1.

a       = θ · s = 0.5 × 1 = 0.5
∂Q/∂a   = −2(a − 2s) = −2(0.5 − 2) = +3.0        hill rises to the right
∂a/∂θ   = s = 1                                   one unit more θ → one unit more torque
∂Q/∂θ   = 3.0 × 1 = 3.0                           (PyTorch autograd also gives 3.0000)
θ_new   = 0.5 + 0.1 × 3.0 = 0.8

step   θ        a        Q        ∂Q/∂θ
 0     0.5000   0.5000   2.7500   3.0000
 1     0.8000   0.8000   3.5600   2.4000
 2     1.0400   1.0400   4.0784   1.9200

Worked example 3: the real actor's tanh layer

Our actor ends with a = 2 · tanh(z) so the torque can never leave [−2, 2]. Toy version: z = θ·s, same critic, θ = 0.5, s = 1. One more link in the chain:

tanh(0.5) = 0.4621        a = 2 × 0.4621 = 0.9242        Q = 5 − (0.9242 − 2)² = 3.8427
∂Q/∂a = −2(a − 2)               = −2(0.9242 − 2)          = 2.1515
∂a/∂θ = 2·(1 − tanh²(z))·s      = 2 × 0.7864 × 1          = 1.5729   (derivative of tanh is 1 − tanh²)
∂Q/∂θ = 2.1515 × 1.5729         = 3.3841                          (autograd: 3.3841)
Notice

If z is large, tanh(z) ≈ ±1 and 1 − tanh² ≈ 0: the actor's gradient almost vanishes. A torque pinned at exactly ±2 learns slowly. You'll see our actors spend a lot of time at ±2 (bang-bang swinging), which is fine for Pendulum.

③ The target networks: soft (Polyak) updates

θtarget  ←  (1 − τ) · θtarget  +  τ · θ        τ = 0.005: keep 99.5% of the old, take 0.5% of the new

Worked example 4: one weight, followed over time

online weight = 0.80 (pretend it stays fixed), target weight starts at 0.50
after 1 step:     0.995 × 0.50 + 0.005 × 0.80 = 0.5015
after 10 steps:   0.5147
after 100 steps:  0.6183
after 138 steps:  0.6498      ← the gap (0.30) has halved: ln 0.5 / ln 0.995 ≈ 138 steps
after 1000 steps: 0.7980      ← almost caught up
by hand with τ = 0.1:  0.50 → 0.5300 → 0.5570 → 0.5813

Formula: after n steps the gap is 0.30 × 0.995n, a geometric sequence. The target follows the online network smoothly, about 140 steps behind, so the Bellman target doesn't jump around.

④ Exploration: wobble the torque

The actor is deterministic: same state, same torque. Without randomness it would never try anything new (like Q-learning with ε = 0). DDPG adds Gaussian noise while training:

a = clip( μ(s) + noise,  −2, +2 )       noise ~ Normal(0, σ = 0.1 × 2 = 0.2)
e.g. μ(s) = 1.30, noise drawn = −0.17  →  a = 1.13 is sent to env.step and stored in the buffer

Plus the first 1,000 steps use completely random torques to fill the buffer. At test time: no noise (like evaluate() using pure argmax in FrozenLake).

06TD3: three fixes, with numbers

Twin Delayed DDPG (Fujimoto et al., 2018). Same code as DDPG plus three if self.td3: blocks.

The problem: the actor hunts for the critic's mistakes

The critic is a learned guess, so some torques are scored too high by luck. The actor is trained to find the torque with the highest score, so it is drawn exactly to those lucky errors. Then the Bellman target uses that inflated score, the error is copied into the next state's value, and so on. Errors that go up get chosen; errors that go down get ignored. On average: too optimistic.

Worked example 5: max of noisy guesses

True value of 5 torques:           10.0   10.0   10.0   10.0   10.0
Critic 1 (with random errors):     10.8    9.5   10.2    9.1   11.3  → max = 11.3   (+1.3 too high!)
Critic 2 (its own random errors):   9.6   10.4   10.9   10.3    9.8
TD3 target uses min(11.3, 9.8) = 9.8                               (−0.2: slightly low, much closer)

hand_examples.py repeats this 100,000 times with 10 actions and errors of size 1:

Estimate used in the targetAverage error (true value 0)
One critic, take the max (DDPG / DQN style)+1.540 (always too high)
Pick with critic 1, score with min(critic 1, critic 2) (TD3)−0.049

And bootstrapping compounds it: each target contains the next state's inflated value. With γ = 0.99 a bias of +1.54 per step can grow toward 1.54 / (1 − 0.99) = 154. A slightly pessimistic critic is much safer than an optimistic one.

Fix 1 · Twin critics, take the min ("clipped double Q")

y = r + γ · min( Q1target(s2, a2), Q2target(s2, a2) )         both critics learn toward the SAME y

Two critics start from different random weights, so they make different mistakes. It's rare that both are too high at the same torque.

Fix 2 · Delayed actor updates

Update the actor (and the target networks) only every 2nd critic update. Climbing a hill that is still being drawn is wasted effort; let the judge settle a bit first. In code: if self.td3 and self.updates % 2 != 0: return.

Fix 3 · Target policy smoothing

A critic can grow a thin, sharp, wrong spike at one exact torque. If the target always asks about exactly μtarget(s2), it keeps hitting the spike. So TD3 jiggles the target torque a little, which averages Q over a small neighbourhood:

a2 = clip( μtarget(s2) + clip(ε, −1.0, +1.0),  −2, +2 )       ε ~ Normal(0, 0.2 × 2 = 0.4)

Worked example 6:  μtarget(s2) = 1.6
   noise drawn +0.3   → inside ±1.0, keep +0.3  → a2 = 1.6 + 0.3 = 1.9
   noise drawn −1.4   → clip to −1.0            → a2 = 1.6 − 1.0 = 0.6
Don't mix up the two noises

Exploration noise (σ = 0.2) goes on the torque sent to the real game. Smoothing noise (σ = 0.4, clipped) goes on the torque a2 inside the Bellman target; the game never sees it.

07SAC: the curious, random actor

Soft Actor-Critic (Haarnoja et al., 2018). The actor outputs a bell curve; the reward includes a bonus for keeping it wide.

① A bell curve instead of one torque

SAC's actor outputs two numbers per action: a mean (centre) and log σ (log of the spread; the log keeps σ positive). The torque is sampled, then squashed:

② The reparameterisation trick, simply

"Draw a random torque from a bell curve" has no slope: you can't ask "how does a dice roll change if I move the mean?" But "take a standard dice roll ε, multiply by σ, add the mean" gives exactly the same kind of random numbers, and it is just algebra: u = mean + σ·ε. With ε fixed after drawing, ∂u/∂mean = 1 and ∂u/∂σ = ε. Now the chain rule from chapter 05 works again.

Worked example 7: one sample, by hand

actor says  mean = 0.3,  σ = 0.5          dice gives ε = 0.8
u        = 0.3 + 0.5 × 0.8                = 0.700
tanh(u)  = tanh(0.7)                      = 0.6044
torque   = 2 × 0.6044                     = 1.2087
slopes   ∂torque/∂mean = 2(1 − tanh²u)    = 1.2695
         ∂torque/∂σ    = 2(1 − tanh²u)·ε  = 1.0156          (PyTorch agrees)

③ The curiosity bonus: −α · log π

π(a|s) is how likely the actor was to pick that torque (a probability density). log π is very negative for an unlikely, surprising pick and large for a pick it was sure about. SAC adds −α · log π to the value: random policies earn more. On average −log π is the entropy H, "how spread out":

Spread σ of a bell curve2.01.00.50.10.01
Entropy H = ½ ln(2πe σ²)+2.112+1.419+0.726−0.884−3.186

Wider = more entropy = bigger bonus. "Reward for staying curious": the policy only narrows its bell curve where being precise clearly pays more than the bonus. Benefits: it explores without hand-made noise, it doesn't bet everything on one torque the critic might be wrong about, and it keeps several good options alive.

Worked example 8: log π for the sample above (with the tanh correction)

log of the bell curve at u:   −½ε² − ln σ − ½ln(2π) = −0.320 + 0.6931 − 0.9189 = −0.5458
tanh squash correction:       − ln(1 − tanh²u) = − ln(0.6347)              = +0.4545
log π(a|s)                    = −0.5458 + 0.4545                            = −0.0913

Why a correction? tanh squeezes the line into (−1, 1), piling probability up near the ends, so the density changes. 1 − tanh² is how much tanh squeezes at that point (the same derivative as in example 3).

④ SAC's Bellman target ("soft" target)

y = r + γ·(1 − done)·[ min( Q1targ(s2, a2), Q2targ(s2, a2) )  −  α · log π(a2|s2) ]
                       ▲ twin critics, like TD3                    ▲ curiosity bonus for s2
    a2 = a FRESH sample from the CURRENT actor in s2 (not from the buffer, no target actor)

Worked example 9: a soft target

r = −1.0,  Q1′ = −15.0,  Q2′ = −15.6,  α = 0.2,  log π(a2|s2) = −0.09
min = −15.6,   bonus −α·log π = −0.2 × (−0.09) = +0.018
y = −1.0 + 0.99 × (−15.6 + 0.018) = −16.4262
   if log π had been +1.5 (very sure):      bonus −0.30  → y = −16.7410
   if log π had been −2.0 (very surprised): bonus +0.40  → y = −16.0480

⑤ The actor's goal and the temperature α

actor:   maximise   min(Q1, Q2)(s, ã) − α · log π(ã|s)      ã = fresh reparameterised sample
α:       if the policy's entropy falls below the target (−1 for one action), raise α; else lower it

α is a thermostat for curiosity. In our run it started at 1.0 and the code lowered it to 0.047 by the end, as the agent became sure what to do (chapter 10 shows the chart). At test time SAC uses the bell's centre, 2·tanh(mean): no randomness.

08The algorithms: flow + pseudocode

One loop for all three; only the "learn" box differs.

DDPG (TD3 changes in blue) 
init actor μ, critic Q1 (+Q2), copies
for each step:
  a = clip(μ(s) + N(0, 0.2))
  s2, r = env.step(a); store row
  batch = 128 random rows
  a2 = μ′(s2) + clip(N(0,0.4), ±1)
  y = r + γ·Q1′(s2,a2)
      → γ·min(Q1′, Q2′)(s2,a2)
  Q1 (Q2) ← toward y
  every 2nd update only:
    μ ← uphill on Q1(s, μ(s))
    all targets ← soft update τ
SAC 
init actor π, critics Q1, Q2, copies, α
for each step:
  a ~ π(·|s)          (no extra noise)
  s2, r = env.step(a); store row
  batch = 128 random rows
  a2 ~ π(·|s2), with log π(a2|s2)
  y = r + γ·[min(Q1′,Q2′)(s2,a2)
             − α·log π(a2|s2)]
  Q1, Q2 ← toward y
  π ← uphill on min Q − α·log π
  α ← up if too sure, down if not
  critic targets ← soft update τ
