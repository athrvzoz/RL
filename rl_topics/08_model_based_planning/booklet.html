01The big picture

You know the two ends. This booklet fills the middle.

Two ways to use a model:

  • Background planning (Dyna-Q): between real moves, replay imagined moves from your notebook to improve the Q-table faster. One real step becomes 1 + n learning updates.
  • Decision-time planning (MCTS): before each move, imagine thousands of possible futures from the current position, then pick the move that came out best. This is how AlphaGo and AlphaZero chose moves.
The one sentence

Model-based RL gets more out of each real experience by thinking: Dyna-Q learns a model from experience and rehearses imagined steps from it; MCTS uses a model (the game's rules) to search ahead with simulations, guided by the same UCB formula you used for bandits.

03Intuition: rehearse, and think ahead

Dyna: rehearsing from your notebook

A student walks once from the school gate to the exam hall and writes down every turn. That night, without walking again, they rehearse the route in their head 50 times: "gate → left → stairs → hall". Next morning they walk it perfectly. One real walk, many mental replays.

MCTS: thinking before you move

A chess player doesn't just play the move that "feels" best. They imagine: "if I play here, they'll probably reply there, then I…". They spend more thought on promising lines and little on silly ones, then play the move that held up best.

Why Q-learning needed so many games

In FrozenLake you measured it: the goal's value reached the start square only in game 70, one square further back per game that happened to pass through. Each real step taught exactly one Q-entry, once. Dyna's answer: keep every real step in a notebook and re-learn from it many times. The value ripple that took 70 real games can happen in your head.

The catch

Planning is only as good as the model. If the notebook is wrong (the world changed, or you remembered badly), you rehearse the wrong route very confidently. Chapter 06 shows exactly this happening, and a fix.

04Dyna-Q: the maths and a hand trace

No new maths: the same Q-learning update, applied to imagined steps too.

REAL step (s, a, r, s′):
  (a) direct RL:     Q(s,a) ← Q(s,a) + α·[ r + γ·max Q(s′,·) − Q(s,a) ]
  (b) model update:  model(s,a) ← (r, s′)                    "write it in the notebook"
  (c) planning, n times:
        pick a remembered (ŝ, â) at random
        (r̂, ŝ′) = model(ŝ, â)                                 "read the notebook"
        Q(ŝ,â) ← Q(ŝ,â) + α·[ r̂ + γ·max Q(ŝ′,·) − Q(ŝ,â) ]       same update, no real move

05Dyna-Q: the algorithm and code

The code: dyna_q.py

def q_update(self, s, a, r, s2, done):
    old = self.Q[s, a]
    target = r + self.gamma * np.max(self.Q[s2]) * (not done)   # your project-3 line
    self.Q[s, a] = old + self.alpha * (target - old)

def plan_once(self):
    s, a = self.seen[self.rng.integers(len(self.seen))]   # a (s, a) we REALLY tried before
    r, s2, done = self.model[(s, a)]                      # ask the notebook (no real move!)
    if self.kappa > 0:                                     # Dyna-Q+: "not checked lately" bonus
        r += self.kappa * math.sqrt(self.t - self.last_tried[(s, a)])
    return ... self.q_update(s, a, r, s2, done)

def learn(self, s, a, r, s2, done):                      # called once per REAL step
    self.q_update(s, a, r, s2, done)                      # (a) direct RL
    self.remember(s, a, r, s2, done)                      # (b) model learning
    return [self.plan_once() for _ in range(self.n_planning)]   # (c) planning
LineMeaning
self.model[(s, a)] = (r, s2, done)The notebook. The maze is deterministic, so one entry per (s, a) is a perfect model of what's been seen.
self.seenPlanning only replays (s, a) pairs that really happened: the model knows nothing about untried moves.
n_planning = 0No planning: exactly Q-learning from project 3.
kappa bonusDyna-Q+: imagined reward grows with √(time since last tried), tempting the agent to re-check old moves.

07Planning at decision time: game trees

Real output of tictactoe_mcts.py part 1.

In board games the rules are known: a perfect model. So before each move you can imagine possible futures. All possible continuations form a game tree.

Tic-tac-toe, full tree: 549,946 positions in the tree, 255,168 different games  (0.5 s to walk it all)
Perfect play from the empty board (minimax): value 0 (a draw)

Rough size of the tree = (moves per turn) ^ (turns per game):
   tic-tac-toe  about   4 ^ 9   = 10^5
   chess        about  35 ^ 80  = 10^124
   Go (19×19)   about 250 ^ 150 = 10^360

Tic-tac-toe can be searched completely (minimax: assume both sides play perfectly and back up the values). Chess and Go cannot: there are more positions than atoms in the universe (about 1080). We need a selective search: think hard about promising moves, ignore hopeless ones. That's MCTS.

The maths: powers and logarithms

3580 = 1080 × log1035 = 1080 × 1.544 ≈ 10124. Every extra move of look-ahead multiplies the work by the number of choices, which is why "just search everything" is hopeless.

09MCTS: the code

mcts.py: the four steps.

def ucb_score(child, parent_N, c):
    exploit = child.W / child.N                                 # average result so far
    explore = c * math.sqrt(math.log(parent_N) / child.N)       # bonus for "not tried much"
    return exploit + explore

for _ in range(n_sims):
    node = root
    # 1. SELECTION: while every move here has been tried, follow the best UCB child
    while not node.untried and node.children:
        node = max(node.children, key=lambda ch: ucb_score(ch, node.N, c))
    # 2. EXPANSION: add one new child (unless the game is already over here)
    if node.untried:
        m = node.untried.pop(rng.randrange(len(node.untried)))
        child = Node(game, game.play(node.state, m), parent=node, move=m)
        node.children.append(child); node = child
    # 3. SIMULATION: random moves to the end of the game
    result = rollout(game, node.state, rng)
    # 4. BACKPROPAGATION: update every node on the path back to the root
    while node is not None:
        node.N += 1
        node.W += score_for(node.just_moved, result)
        node = node.parent
LineMeaning
game.play(state, m)The model: the rules tell us exactly what the board looks like after a move.
node.just_movedEach node scores results for the player who moved into it, the one choosing it at the parent. So X picks moves good for X, O picks moves good for O: minimax, approximately.
rollout()A quick, random "guess" of how good a position is: play randomly to the end. Many noisy guesses average out.
best_move = most visitedVisits are a steadier vote than win rate: a move tried twice with 2 wins is less trustworthy than one tried 400 times with a 70% rate.

12The AlphaZero idea

Replace "try everything and play randomly to the end" with a neural network's intuition.

Random rollouts are a poor judge in big games: a random game of Go says almost nothing about who's winning. AlphaZero (DeepMind, 2017; for Go, chess and shogi) changed two things in MCTS:

Plain MCTSAlphaZero-style MCTS
new moves tried in random ordera policy network gives each move a prior P: "this move looks promising"
leaf judged by a random rollouta value network judges the position directly: "X is winning, about +0.6"
UCB: W/N + c·√(ln Np/N)PUCT: Q + c·P·√Np / (1 + N): the prior P scales the exploration bonus

  • Search improves even a decent hint: the prior alone plays 78.7% perfect; with search it reaches 95–98%.

MuZero, in one paragraph

AlphaZero still needs the game's rules (game.play). MuZero (DeepMind, 2019/2020) also learns the model: a network predicts the next hidden state and reward, and MCTS plans inside that learned model. That puts it in Dyna's spirit (a learned model) with AlphaZero's search, and it was also applied to Atari games, where nobody gives you the rules.

13Real-world problems

When model-based methods fit

✔ Real experience is expensive but thinking is cheap. ✔ You know the rules (games, puzzles, logistics with known travel times) or can learn a decent model. ✘ The world is too messy to model well: errors in the model get planned on confidently ("planning in a wrong map").

1 · Board games (well documented)

AlphaGo beat world champion Lee Sedol at Go in 2016 (MCTS + policy and value networks, initially trained on human games); AlphaZero learned Go, chess and shogi from self-play alone (2017). State = board, action = legal move, reward = +1/0/−1 at the end, model = the rules. Exactly chapters 08–12, at enormous scale.

2 · A delivery robot in a warehouse

Staterobot position, carried item, positions of shelves and other robots
Actionmove in 4 directions, pick, drop
Reward−1 per move, +20 per delivery, −50 for collisions
Modellearned: "moving right from aisle 3 takes me to aisle 4 (unless blocked)"
Why DynaReal driving is slow and wears out the robot; replaying the notebook overnight improves the plan for free. Use Dyna-Q+'s bonus because shelves get moved (the blocking maze!).

3 · Planning routes or schedules with known rules

Statejobs remaining, machine availability, time
Actionwhich job to put on which machine next
Reward−(total lateness) at the end
Modelgiven: job durations are known, so you can simulate schedules
Why MCTSToo many orderings to try all (a tree like chess), but simulation is cheap and exact. MCTS has been studied for scheduling and planning problems ("could be used for").

4 · Model predictive control (robots, self-driving research)

At every moment: use a model of the physics to imagine the next few seconds for several candidate action sequences, carry out the first step of the best one, then re-plan. It's decision-time planning, like MCTS but with continuous actions. Widely used in industrial control; learned models (as in MuZero/Dyna) are an active research area.

15Clearing up the confusions

Is Dyna's "model" a neural network?

Not here: it's a dictionary, (s, a) → (r, s′). For big or continuous worlds the model can be a network (as in MuZero), but the idea is the same.

Do planning steps use a different update than Q-learning?

No. Exactly the same Bellman update. Only the source of (s, a, r, s′) differs: the notebook instead of the world.

Can Dyna imagine moves it has never tried?

No. The notebook only contains what really happened. Planning spreads known information around; it can't invent new facts. (Dyna-Q+ "pretends" untried moves stay put with reward 0, purely to give them a curiosity bonus.)

Why didn't more planning (n = 100) beat n = 50?

Once the Q-table agrees with the notebook, extra replays change little. The remaining cost is exploring game 1 and random ε moves, which thinking can't remove.

Is MCTS's "backpropagation" the same as in neural networks?

No, an unlucky shared name. In MCTS it means "add this simulation's result to every node on the path". In networks it means computing gradients with the chain rule.

Does MCTS learn anything between moves?

Plain MCTS: no. It builds a fresh tree each turn and throws it away. AlphaZero adds learning by training its networks on the search results.

Why play the most visited move, not the best win rate?

UCB sends visits to moves that keep looking good, so visits are a reliable vote. A rarely visited move's win rate is based on very few games and could be luck.

How is this related to the Monte Carlo booklet?

"Monte Carlo" = estimate by averaging random samples. Rollouts are Monte Carlo estimates of a position's value; MCTS organises them into a tree.

Did AlphaZero use the Bellman equation?

Not directly: its value network learns from who actually won the self-play games (a Monte Carlo target), and its policy learns from MCTS visit counts. Search does the "look-ahead" job that bootstrapping does in TD methods.

Four sentences to remember
  1. A model predicts what happens after an action; planning means learning or deciding with imagined experience from it.
  2. Dyna-Q writes a notebook from real steps and replays it n times per step with the normal Q-learning update: far fewer real steps (game 30 → game 3).
  3. MCTS searches ahead before each move: select by UCB, expand, simulate randomly, back up the result; then play the most visited move.
  4. AlphaZero replaces random choices with a network's priors and value, and improves that network from its own searches through self-play.
