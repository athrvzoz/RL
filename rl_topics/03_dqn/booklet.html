01The big picture

Your Q-table worked for 16 squares and 500 taxi states. What about infinitely many?

FrozenLake had 16 states, so Q was a 16 × 4 table. Taxi had 500 states: 3,000 numbers. Now look at CartPole: a pole balanced on a cart. Its state is 4 real numbers: cart position, cart speed, pole angle, pole spin. A real number can be 0.0312 or 0.0313 or anything in between. There are infinitely many states. You cannot make a table with a row for each.

Even if you rounded the numbers, you'd hit the second problem from your earlier question: a state the agent never visited has an empty row, so it knows nothing there. In a world with millions of states, almost every state is new.

The one sentence

DQN is Q-learning where the Q-table is replaced by a neural network: you feed in the state's numbers and it outputs one Q-value per action. It learns by shrinking the gap between its guess and the same Bellman target, r + γ·max Q(s2), and it needs two tricks (a replay buffer and a target network) to stay stable.

This is the method DeepMind used in 2015 to learn to play 49 Atari games from screen pixels, many at a human level, with one algorithm and the same settings for every game (published in Nature). It was the start of "deep reinforcement learning".

03Intuition: memorise vs understand

A Q-table memorises answers. A network learns a rule.

Student A: memorises (Q-table)

Writes down the answer to every exam question ever seen. Perfect on repeats. A new question? Blank page.

Student B: understands (network)

Learns the method behind the answers. A new question similar to old ones? A sensible answer. Sometimes wrong, but never blank.

CartPole, the game for this booklet

              |          pole: keep it upright
              |
          ____|____
         |  cart   |  ← push left (action 0)   push right (action 1) →
   ======O=========O======    track

state  = [cart position, cart speed, pole angle, pole spin]      (4 real numbers)
reward = +1 for every step the pole stays up
ends   = pole tilts past ~12°, or cart leaves the track (terminated)
         or 500 steps reached: a perfect game (truncated)

A human solution is easy to say: "if the pole leans right, push the cart right", like balancing a stick on your palm. That rule depends on the angle and spin, not on memorising exact numbers. A network can discover exactly this kind of rule.

The key idea: similar states, similar answers

Angles of 0.050 and 0.051 radians are basically the same situation. A table treats them as strangers. A network gives them almost the same Q-values automatically. So every experience teaches it about many states at once. That's also part of the answer to "how can the agent know about states it never visited?": by similarity.

04Maths I: a neural network by hand

Real output of python hand_example.py. The maths: dot products and matrix multiplication.

A tiny network: 2 inputs → 2 hidden neurons (ReLU) → 2 outputs. The real CartPole network is the same thing, just bigger (4 → 64 → 64 → 2).

The numbers

s  = [1, 2]
W1 = [[0.5, −0.2],     b1 = [0.1, −0.4]          W2 = [[1.0, −1.0],     b2 = [0.0, 0.2]
      [0.3,  0.1]]                                     [0.5,  2.0]]

Step 1: hidden layer = matrix × vector + bias

z1 = 0.5×1 + (−0.2)×2 + 0.1 = 0.20         ← row 1 of W1 · s  (a dot product) + bias
z2 = 0.3×1 + 0.1×2 − 0.4    = 0.10         ← row 2 of W1 · s + bias
ReLU: h1 = max(0, 0.20) = 0.20    h2 = max(0, 0.10) = 0.10

Step 2: output layer

Q(left)  = 1.0×0.20 + (−1.0)×0.10 + 0.0 = 0.10
Q(right) = 0.5×0.20 + 2.0×0.10 + 0.2    = 0.50     → the network prefers RIGHT

That's all a forward pass is: W1·s + b1 → ReLU → W2·h + b2. In matrix form, "W1 · s" is the matrix multiplication from school: each row of W1 dotted with the vector s.

How big is the real one?

CartPole's network: 4 → 64 → 64 → 2. Weights: 4×64 + 64×64 + 64×2 = 4,480, plus 64 + 64 + 2 = 130 biases → 4,610 knobs. It covers infinitely many states with 4,610 numbers. Taxi's table needed 3,000 numbers for just 500 states.

05Maths II: loss, gradient, backprop

How the network learns from one move. The maths: squaring, derivatives and the chain rule.

From "nudge the table" to "shrink the loss"

Tabular Q-learning (project 3):   Q[s,a]  ←  Q[s,a] + α · (target − Q[s,a])
DQN:                              change the WEIGHTS θ so that  Qθ(s,a)  moves toward the target

    loss  L(θ)  =  ( target  −  Qθ(s, a) )²         target = r + γ · maxa′ Qtarget net(s2, a′)
                     ▲ fixed number   ▲ depends on θ           (0 future if the game ENDED)

The loss for one move (real numbers)

took RIGHT, r = 1.0, best Q in s2 (from the target net) = 1.0,  γ = 0.9
target = 1.0 + 0.9 × 1.0 = 1.90
loss   = (1.90 − 0.50)² = 1.9600

Backprop = the chain rule, one link at a time

The loss depends on Q(right), which depends on the hidden values h, which depend on the first-layer weights. To know how one weight affects the loss, multiply the links of that chain:

dL/dQ          = −2 × (target − Q)            = −2 × 1.40       = −2.80

dL/dW2[right,1] = dL/dQ × dQ/dW2[right,1]     = −2.80 × h1(0.20) = −0.560
dL/dW2[right,2] = dL/dQ × h2                  = −2.80 × 0.10     = −0.280

dL/dh1          = dL/dQ × W2[right,1]          = −2.80 × 0.5      = −1.400
ReLU's derivative: 1 if z > 0, else 0.   z1 = 0.20 > 0 → passes
dL/dW1[1,1]     = dL/dz1 × s1                  = −1.400 × 1.0     = −1.400

A negative derivative means "increase this weight and the loss goes down". So gradient descent increases these weights.

One gradient-descent step (learning rate 0.01, all weights updated)

every weight:   w  ←  w − 0.01 × dL/dw

Q(s, right): 0.500 → 1.245    (target 1.90)   new loss 0.4293 (was 1.9600)
Q(s, left):  0.100 → −0.152   ← it also changed, though we only trained "right"!
Generalisation is a double-edged sword

Q(left) moved because both outputs share the hidden layer. That's the good side (learning spreads to related states and actions) and the risky side (fixing one answer can disturb others). A Q-table never had this problem: changing Q[14, right] left everything else alone. Chapter 06 is about taming this.

06Why the simple version breaks

"Q-learning + a neural network" sounds easy. Done naively, it often fails. Three problems, three fixes.

Problem 1: consecutive moves are too similar

In CartPole, step 101 looks almost exactly like step 100. Training on moves in order is like studying 200 questions about one chapter, then 200 about the next: the network over-fits to "now" and forgets the rest.

Fix: the replay buffer. Store every move (s, a, r, s2, ended) in a notebook of up to 50,000 moves. Each training step, learn from a random batch of 64 old moves. Bonus: every move gets reused many times instead of once.

Problem 2: the target moves while you chase it

The target r + γ·max Q(s2) is computed by the same network you are changing. Each update moves Q(s2) too, so the target runs away: like a dog chasing its own tail.

Fix: the target network. Keep a frozen copy of the network for computing targets, and copy the online weights into it only every 500 steps. For 500 steps the target stands still, so the online network can actually reach it.

Problem 3: max is over-optimistic

The network's Q-values are noisy guesses. Taking the max of noisy guesses picks whichever one happens to be too high. Real output of hand_example.py part 5 (4 actions, all truly worth 0, noise of size 1):

average of ONE estimate:                                       +0.004   (fine)
average of the MAX of the 4 estimates:                         +1.031   ← too high!
Double trick: pick with one estimate, value with another one:  +0.008   (fine again)

And the error feeds itself: the too-high max becomes the target, the next max is even higher… Fix: Double DQN. Let the online net choose the best next action, but let the target net score it. Two different noisy estimates rarely agree on the same lucky mistake.

DQN:         target = r + γ · maxa′ Qtarget(s2, a′)
Double DQN:  a* = argmaxa′ Qonline(s2, a′),    target = r + γ · Qtarget(s2, a*)

07The algorithm

Steps 1–3 are exactly project 3. Steps 4–7 replace the one-line table update.

Pseudocode

online = new network;  target = copy(online);  buffer = empty;  ε = 1.0
s = reset()
for step = 1 … 50,000:
    a = random action with probability ε, else argmax online(s)
    s2, r, ended = step(a);   buffer.add(s, a, r, s2, ended);   s = s2 (or reset if over)
    ε = max(0.05, ε × 0.9995)
    if step ≥ 1,000:                                   # collect some moves first
        batch = 64 random moves from buffer
        y = r + γ · maxa′ target(s2)[a′] · (1 − ended)      # no gradient through y
        loss = Huber(online(s)[a], y)
        loss.backward();  optimizer.step()             # backprop + gradient descent
    if step % 500 == 0:  target = copy(online)

08The code, line by line

dqn.py, the library used by every script.

① The network

class QNetwork(nn.Module):
    def __init__(self, n_inputs, n_actions, hidden=64):
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(n_inputs, hidden), nn.ReLU(),   # layer 1: W1·s + b1, then ReLU
            nn.Linear(hidden, hidden), nn.ReLU(),     # layer 2
            nn.Linear(hidden, n_actions),             # output: Q(s, left), Q(s, right)
        )

② The replay buffer

class ReplayBuffer:
    def __init__(self, capacity):
        self.memory = deque(maxlen=capacity)          # old pages fall out when full
    def add(self, s, a, r, s2, terminated):
        self.memory.append((s, a, r, s2, terminated))
    def sample(self, batch_size):
        batch = random.sample(self.memory, batch_size)  # a RANDOM mix of old moves
        return to_tensors(batch)

③ The Bellman target (plain or Double)

def compute_targets(online, target_net, r, s2, term, gamma, double):
    with torch.no_grad():                           # targets are NOT trained
        if double:
            best_a = online(s2).argmax(dim=1, keepdim=True)        # online net CHOOSES
            q_next = target_net(s2).gather(1, best_a).squeeze(1)   # target net SCORES
        else:
            q_next = target_net(s2).max(dim=1).values              # plain DQN
        return r + gamma * q_next * (1 - term)                 # your old target line!

④ The learning step inside train()

bs, ba, br, bs2, bterm = buffer.sample(batch_size)              # 64 random OLD moves
q_taken = online(bs).gather(1, ba.unsqueeze(1)).squeeze(1)       # Q(s, a) for the action taken
target = compute_targets(online, target_net, br, bs2, bterm, gamma, double)
loss = loss_fn(q_taken, target)                                  # how wrong were we?
optimizer.zero_grad()
loss.backward()                                                  # backprop: chain rule, done for us
nn.utils.clip_grad_norm_(online.parameters(), 10.0)              # safety: limit huge gradients
optimizer.step()                                                 # gradient descent: nudge every weight
...
elif use_target and step % target_every == 0:
    target_net.load_state_dict(online.state_dict())              # refresh the frozen copy
LineMeaning
online(bs).gather(1, ba…)The network outputs both Q-values for each of the 64 states; gather picks the one for the action actually taken. Only that one is trained, like Q[s, a] in project 3.
torch.no_grad()The target is treated as a fixed number. We don't adjust weights to move the target toward Q, only Q toward the target.
(1 - term)Same as project 3's (not terminated): pole fell → no future. Hitting 500 steps is truncated, so the future still counts.
loss.backward()PyTorch does all of chapter 05's chain-rule work for 4,610 weights automatically.
optimizer.step()Adam's gradient-descent step, learning rate 0.0005.
eps * eps_decay (per step)ε falls from 1.0 to 0.05 over about 6,000 steps (0.99956000 ≈ 0.05).
best-network copyEvery 2,500 steps the code tests the network with no exploration and keeps the best version. DQN's score can drop later (chapter 09), so we keep the best.

What to notice (honestly)

  • It learned fast: after only 143 games (2,500 steps) the greedy test already scored 431. A random player scores about 22.
  • Then it wobbled: test scores swung between 110 and 360 for the rest of the run. This is the famous instability of DQN: improving Q for some states disturbs others (chapter 05's shared weights), and the buffer fills with "good" states so it forgets what danger looks like.
  • Keeping the best network matters: the saved best version averages 472.9 out of 500 over 100 fresh games. Real DQN projects always keep checkpoints, for exactly this reason.
  • The loss is not a scoreboard: it doesn't go down steadily, because the targets keep moving. Judge an RL agent by its score, not by its loss.

Two lessons in one table
  • It discovered the human rule "push toward the side the pole leans", without anyone telling it. Nobody wrote this rule into the code.
  • The values are far from "true": about 3, while a perfect player's true Q is close to 100 (= 1/(1 − 0.99)). The best network came from step 2,500, very early, before the values had grown. It still plays well because choosing an action only needs the order of Q(left) and Q(right) to be right, not their size. Nearly-falling states correctly get lower values (2.6–2.8) than calm ones (3.2).

What each result teaches

  • No target network → total collapse. Q-values grew to about 20 million, when no true value can exceed 100. Each update raised Q(s, a), which raised the target max Q(s2), which raised Q again: the dog chasing its tail, faster and faster. The agent scored 9, worse than random. This is the "moving target" problem of chapter 06, in real numbers.
  • No replay buffer → very slow and fragile. Learning only from the move just made gave a mean test score of 31.9 during training; one seed finally jumped up near the end. Consecutive CartPole moves are too similar to teach a network well.
  • Full DQN works but wobbles, as in chapter 09: good versions appear (best 474.6 for seed 0), then get worse again.
  • Double DQN was the only variant to reach a perfect 500 (seed 0), and had the best final and best networks on average. Honestly, its Q-values were not lower here (56.7 vs 55.4): on a game as simple as CartPole the over-optimism of chapter 06 is small. Double DQN's advantage was measured mostly on harder games such as Atari.
  • 2 seeds is not much. RL results vary a lot from seed to seed (look at full DQN: 474.6 vs 256.5). Serious comparisons use 5–10+ seeds. Treat small differences here as hints, big ones (9 vs 190) as real.

11Real-world problems

DQN fits when the state is a vector (or image) of numbers and there are a few discrete actions.

When DQN fits

✔ Many or continuous states. ✔ A small set of discrete actions (you need max over actions). ✔ A simulator or lots of logged data (DQN is off-policy, like Q-learning). ✘ Continuous actions (a steering angle, a motor torque): you can't take max over infinitely many actions. Use booklet 07 (DDPG/SAC) or PPO instead.

1 · Atari games from pixels (well documented)

Statethe last 4 screen frames (84×84 grey pixels), so the network can see motion
Actionjoystick moves: up to 18 discrete choices
Rewardchange in game score (clipped to −1/0/+1)
What changes from CartPoleThe network starts with convolutional layers (pattern detectors for images). Everything else is the DQN you just learned: replay buffer, target network, ε-greedy. DeepMind's 2015 Nature paper used this setup on 49 games.

2 · Data-centre cooling or a building's AC

Statevector of temperatures, power use, outside weather, time of day
Actiona few discrete settings: fan speed levels, chiller on/off
Reward−energy cost − big penalty if any temperature goes over the safe limit
Why DQNContinuous sensor readings (no table possible), few discrete actions, and years of logged data to train off-policy. DeepMind reported cutting cooling energy at Google data centres using machine learning; treat the exact method as "deep RL-style control", and our formulation as a simplified version.
PitfallSafety: never let the learning agent act unsupervised at first. Use safety limits and human override.

3 · Which offer to show a shopper next

Stateuser features: recent clicks, time on site, basket value, device
Actionone of 10 offers (or "no offer")
Reward+profit if they buy in the session, small −cost of a discount
Why DQNIt values long-term effects (an offer now may cause a purchase three pages later), unlike a one-step bandit. It could be used for this; real systems combine it with careful offline evaluation.
PitfallThe logged data came from the old policy: Q-values for rarely shown offers are unreliable (the overestimation problem in real life).

13Clearing up the confusions

Is the Bellman target different in DQN?

No. Still r + γ·max Q(s2), with no future if the game ended. Only who computes it (the frozen target network) and how Q moves toward it (gradient descent) change.

What does the network output: an action, a probability or a value?

Values: one Q-number per action. The action is chosen by argmax (or randomly with ε). It does not output probabilities; that's what policy methods (booklet 04) do.

Which state's Q gets trained?

Q(s, a) for the state you left and the action you took, for 64 old moves at once. Q(s2) is only read (from the target network), exactly like project 3.

If I train Q(s, right), why does Q(s, left) change too?

Both outputs share the hidden layers. Changing shared weights moves every output a bit. Part 4 of the hand example: Q(left) went 0.100 → −0.152.

How can it know a state it has never seen?

It can't know, but it can guess well: a new state with similar numbers produces similar outputs. That's generalisation. A table can't do this at all.

Why learn from old moves? Aren't they outdated?

The Bellman target only needs (s, a, r, s2): what the world did. That stays true no matter which policy chose the action. That's why off-policy methods can use a replay buffer. On-policy methods like SARSA or PPO can't, at least not directly.

Why does the loss not go steadily down?

The targets keep changing: every 500 steps the target network is refreshed, and as the agent gets better it reaches new states with new targets. The loss is not a scoreboard in RL; the game score is.

Why is the largest Q about 100 in CartPole?

Reward +1 per step and γ = 0.99: 1 + 0.99 + 0.99² + … = 1/(1 − 0.99) = 100. A Q-value far above 100 is over-optimism.

Is "deep" just "many layers"?

Yes, "deep" means a neural network with more than one hidden layer. Our network has two hidden layers of 64.

Can DQN steer a car with any angle between −30° and +30°?

Not directly: it needs max over actions, and infinitely many angles can't be listed. You could chop the angle into, say, 7 options, but continuous methods (DDPG, SAC, PPO) are the proper tool.

Why does the score sometimes collapse after reaching 500?

A known DQN weakness ("catastrophic forgetting"): once it plays well, the buffer fills with "good" states, it forgets what bad states look like, and Q-values drift. That's why the code keeps the best network seen.

DQN in 10 lines 
online, target = net, copy(net)
for every step:
  a = ε-greedy(online(s))
  s2, r, end = step(a); store it
  batch = 64 random stored moves
  y = r + γ·max target(s2)·(1−end)
  loss = Huber(online(s)[a], y)
  backprop; gradient step
  every 500 steps: target = online
  shrink ε
Key formulas 
Layer:    h = ReLU(W·s + b)
Loss:     L = (y − Q(s,a))²
Gradient: w ← w − lr · dL/dw
Chain:    dL/dw = dL/dQ · dQ/dh · dh/dw
DQN y:    r + γ max Q_tgt(s2)
Double y: r + γ Q_tgt(s2, argmax Q_onl)
Max Q:    1/(1−γ) for reward 1/step
Four sentences to remember
  1. DQN replaces the Q-table with a neural network that calculates Q-values from the state's numbers, so it works with huge or continuous state spaces.
  2. The target is still r + γ·max Q(s2); the network moves toward it by gradient descent on the squared error (backprop = chain rule).
  3. A replay buffer (random old moves) and a target network (a frozen copy) are what make it stable.
  4. max over noisy guesses is too optimistic; Double DQN lets one network choose and the other score.
