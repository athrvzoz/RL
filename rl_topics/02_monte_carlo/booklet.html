01The big picture

You asked once: "Does Q-learning wait until the end of the game and then update everything backwards?" It doesn't. Monte Carlo does.

You have built three things so far. Each one answers "how good is this?" in a different way:

  • Bandit (one state, no future): Q[a] = the average of the rewards you got from arm a. Update: Q += (r − Q)/N.
  • Value iteration: has the rule book, so it calculates every square with Bellman. Never plays.
  • Q-learning: no rule book. After every step it nudges Q[s,a] toward r + γ·max Q[s2], a target that contains a guess (Q[s2]).

Monte Carlo (MC) is the bandit idea stretched over a whole game. No rule book, no guesses. It plays one full game, waits for the end, then for every state it visited it writes down the real total reward that came after, and averages those totals. That's all.

The one sentence

Monte Carlo plays a complete game, then walks backwards through it, giving every (state, action) it visited the real total reward that followed, and keeps a running average of those totals, exactly like the bandit, but one average per state.

What problem does it solve that you couldn't before?

ProblemWhy your old tools struggleMonte Carlo
No rule bookValue iteration needs P(s′|s,a). In Blackjack nobody gives you card probabilities.Only needs to play

03Intuition: learn from the final score

Some results only exist at the end. You can't know who won a cricket match after the 10th over.

The cricket coach

A coach wants to learn: "When we are at 60 for 2 after 10 overs, how likely are we to win?" She can't calculate this from a rule book: nobody knows the exact probability of every ball. So she does the obvious thing:

  1. She watches whole matches. During the match she just writes down the situations: "10 overs: 60/2", "20 overs: 110/4", …
  2. When the match ends she knows the result: won (+1) or lost (−1).
  3. She goes back through her notebook and writes that result next to every situation from that match.
  4. Over many matches, "60/2 after 10 overs" collects a list of results: +1, −1, +1, +1 … Its average is her answer.

That is Monte Carlo prediction, exactly. The notebook is the episode record, the result is the return G, and the average is V(s).

Compare: how would a Q-learning coach do it?

She would update after every over: "We were 60/2 and now we're 110/4. My table says 110/4 wins 55% of the time, so 60/2 must be worth about that." She never waits for the result, she trusts her table for the next situation. Fast, but only as good as her table. The MC coach never trusts her table; she only trusts finished matches.

A tiny example you can do by hand

One state we care about: "my sum is 20, dealer shows 10". We play "stick on 20" (so we always stick here). Five games happened to pass through this state. Their final results:

Notice what is NOT here

No probability of cards. No γ·V(next state). No guess of any other state. Just finished games and an average. This is why MC is the easiest RL method to trust: if you average enough real results, you get the right answer.

04The maths, step by step

Only three ideas: a sum (the return), an average (the value), and a shortcut for the average (the incremental mean).

① The return G: "everything that came after"

Number the rewards after time t as r1, r2, r3, … until the end. The return from time t is

G  =  r₁  +  γ·r₂  +  γ²·r₃  +  …  +  γ^(T−1)·r_T
▲     ▲      ▲                         ▲
a     reward discounted                last reward, then the game ENDS
NUMBER the    once (one step later)     (no more terms: that's why MC needs an end)
      next step

This is the same quantity Bellman talks about. In project 2 you saw: V(s′) = r′ + γr″ + …, "V already contains the whole future". The difference is: Bellman predicts it, MC measures it by playing to the end.

② Computing G backwards: one multiply and one add per step

Take the formula for time t and pull out the first reward:

G_t  = r_(t+1) + γ·r_(t+2) + γ²·r_(t+3) + …
     = r_(t+1) + γ·( r_(t+2) + γ·r_(t+3) + … )      ← take γ out of everything after the first term
     = r_(t+1) + γ·G_(t+1)                           ← the bracket IS the return from the next step

So start at the last step (G = last reward) and walk backwards: G ← r + γ·G. This looks just like the Bellman target r + γ·V(s′), but with the real G of the next step instead of a guess V(s′). (School maths used: factorising, and a finite geometric-style sum.)

Worked example 1: one game, γ = 0.9

Game:   A ──(r = 0)──► B ──(r = −1)──► C ──(r = +10)──► END

Forwards (the definition), from A:   G_A = 0 + 0.9·(−1) + 0.9²·(10) = 0 − 0.9 + 8.1 = 7.2

Backwards (what the code does):
  start at the end         G = 0
  C:  G = 10 + 0.9 × 0      = 10.0     → return from C is 10.0
  B:  G = −1 + 0.9 × 10.0   =  8.0     → return from B is  8.0
  A:  G =  0 + 0.9 × 8.0    =  7.2     → return from A is  7.2   ✓ same as forwards

Backwards is cheaper: one pass gives the return of every step. Forwards you would redo the sum for each step.

③ The value is an average of returns

The true value of a state is the expected return (the average over infinitely many games):

V_π(s) = E_π[ G | start at s ]          "average of G over all games that pass through s,
                                          playing policy π"
estimate after N games:   V(s) ≈ ( G⁽¹⁾ + G⁽²⁾ + … + G⁽ᴺ⁾ ) / N

Why does this work? The law of large numbers from probability: the average of many independent samples gets closer and closer to the expectation. The uncertainty shrinks like 1/√N, so 4× more games ⇒ half the error.

④ The incremental mean: your bandit rule

We don't want to store every G. Let VN be the average of N returns. Derivation:

V_N = (G⁽¹⁾ + … + G⁽ᴺ⁻¹⁾ + G⁽ᴺ⁾) / N
    = ( (N−1)·V_(N−1) + G⁽ᴺ⁾ ) / N           ← the first N−1 returns add up to (N−1)·V_(N−1)
    = V_(N−1) − V_(N−1)/N + G⁽ᴺ⁾/N            ← split the fraction
    = V_(N−1) + ( G⁽ᴺ⁾ − V_(N−1) ) / N        ← group: old + (new − old)/N
      ▲          ▲        ▲          ▲
      old guess  NEW real old guess  step size 1/N (shrinks: later games move it less)
                 return

In the bandit you wrote Q[a] += (r − Q[a]) / N[a]. Monte Carlo is V[s] += (G − V[s]) / N[s]: the reward r became the return G, and the single arm became a state. That's the whole link.

Constant step size α

Replace 1/N by a fixed α (say 0.05): V += α(G − V). Now recent games count more than old ones. Useful when the policy keeps changing (control), and it makes MC look exactly like Q-learning's update with a different target:
MC: V(s) ← V(s) + α[G − V(s)]   ·   TD: V(s) ← V(s) + α[r + γV(s′) − V(s)]

Worked example 2: the same game, MC update with α = 0.5

Old guesses before the game: V(A) = 2, V(B) = 4, V(C) = 6. Returns from example 1: 7.2, 8.0, 10.0.

C:  V(C) = 6.0 + 0.5 × (10.0 − 6.0) = 8.0
B:  V(B) = 4.0 + 0.5 × ( 8.0 − 4.0) = 6.0
A:  V(A) = 2.0 + 0.5 × ( 7.2 − 2.0) = 4.6       ← A learned from C's +10 in ONE game

(Printed by python mc_vs_td.py, part 1. Chapter 11 does the same game with TD.)

⑤ First-visit vs every-visit

If a state appears twice in one game, which return do we use?

Worked example 3 (γ = 1)

Game:  A ──(r = 1)──► B ──(r = 0)──► A ──(r = 2)──► END

backwards:   step 2 (A):  G = 2          step 1 (B):  G = 0 + 2 = 2     step 0 (A):  G = 1 + 2 = 3

first-visit MC:  V(A) gets ONE sample:  3                 (only A's first appearance)
every-visit MC:  V(A) gets TWO samples: 3 and 2 → mean 2.5

Both are correct in the long run. First-visit gives independent samples (one per game), which makes the maths of "average → expectation" clean. In Blackjack the question never arises: your sum only goes up (and a usable ace only turns into a non-usable one), so no state can repeat within a game. Our run checked 100,000 games: 0 repeats, and first-visit and every-visit gave identical V.

⑥ From V to Q, and from grading to improving

Without a rule book, V alone can't choose a move (you'd need to know which action leads where; same reason Q-learning uses Q). So for control, MC averages returns per (state, action):

Q(s, a) ≈ average of the returns that followed "doing a in s"
policy:  in each state pick argmax_a Q(s, a)      (with chance ε, pick randomly instead)

Playing with the greedy policy makes the averages better, better averages make the policy better: generalised policy iteration, the same "evaluate ↔ improve" loop that value iteration did in one formula.

05The algorithm

Play → wait for the end → walk backwards → update every visited pair → repeat.

"Wait until the end, then update backwards": the picture

The control loop

Pseudocode

MC prediction (grade a fixed policy π)

V(s) = 0, N(s) = 0 for all s
repeat for many games:
  play a game with π, record
     s₀,a₀,r₁, s₁,a₁,r₂, …, END
  G = 0
  for t = last … 0:  # backwards
    G = r_(t+1) + γ·G
    if first visit of s_t:
      N(s_t) += 1
      V(s_t) += (G − V(s_t)) / N(s_t)

MC control (on-policy, ε-greedy)

Q(s,a) = 0, N(s,a) = 0
repeat for many games:
  play a game with ε-greedy(Q),
     record (s, a, r) per step
  G = 0
  for t = last … 0:  # backwards
    G = r_(t+1) + γ·G
    if first visit of (s_t, a_t):
      N(s_t,a_t) += 1
      Q(s_t,a_t) += (G − Q)/N
policy = argmax_a Q(s, a)

Why exploration is still needed

If the policy is greedy, an action that looked bad early is never tried again, so its average never gets corrected. Two fixes:

  • ε-greedy (what we use): every action keeps at least an ε/2 chance in Blackjack (2 actions). The policy we learn is the best ε-greedy policy; at test time we drop ε.
  • Exploring starts: start every game from a random state with a random first action, then be fully greedy. Every (s, a) pair gets started from sometimes. Easy in a simulator, impossible in real life (you can't "start" a patient in a random state). Chapter 10 tries it.

06Blackjack: the game

gym.make("Blackjack-v1"), Sutton & Barto rules (the default, sab=True).

  • You and the dealer get 2 cards. You see one dealer card.
  • Cards: 2–9 as printed, J/Q/K count 10, ace counts 1 or 11. Infinite deck (cards drawn with replacement).
  • Goal: get closer to 21 than the dealer without going over ("bust").
  • Hit (action 1): take a card. Over 21: you lose at once.
  • Stick (action 0): stop. Then the dealer draws until 17 or more. Higher sum wins; dealer bust = you win.
  • Reward: +1 win, 0 draw, −1 loss, and 0 on every step before the end. γ = 1.
PieceIn Blackjack-v1
State(your sum, dealer card, usable ace)
e.g. (13, 2, 1) = soft 13 vs a 2
Actions0 = stick, 1 = hit
Rewardonly at the end: +1 / 0 / −1
Episodeone hand; usually 1–3 decisions
States that mattersum 12–21 × dealer A–10 × ace yes/no = 200 (the run saw 280 including sums 4–11)

Why Blackjack is the perfect Monte Carlo game

  • The only reward is at the end. Every step before gives 0. With γ = 1, the return of every state in a game is simply the final result. MC gives each visited state the answer after one game; Q-learning must pass it back step by step through guesses.
  • Nobody hands you the rule book. You could in principle calculate the dealer's chances of reaching 17, 18, … 21 or busting from every up-card, but it's messy. MC just plays, millions of times if needed. Simulating a hand takes microseconds.
  • Games always end, quickly. MC's one hard requirement is met.
Action probabilities vs environment probabilities

Two different kinds of chance appear in this booklet. The deck decides which card comes: that's the environment, MC never sees those probabilities. The policy decides hit or stick: "stick on 20" is deterministic, ε-greedy and the random player have action probabilities. Importance sampling (chapter 12) uses only the action probabilities, never the deck's.

The two policies we start from

PolicyRuleIn code
Stick on 20+ (the simple one)Hit until your sum is 20 or 21, then stick.STICK if s[0] >= 20 else HIT
RandomFlip a coin at every decision.rng.integers(2)

"Stick on 20" sounds bold. It is: it hits on 18 and 19, which usually busts. Monte Carlo will show exactly how bad that is, state by state, and then find something much better.

07The code, line by line

mc.py: shared by every script. Real excerpts.

① Playing one game: just record, learn nothing

def play_episode(env, policy, rng):
    episode = []
    s = as_state(env.reset()[0])
    done = False
    while not done:
        a = policy(s, rng)
        obs, r, terminated, truncated, _ = env.step(a)       # the only contact with the world
        episode.append((s, a, r))                               # reward that came AFTER a in s
        s = as_state(obs)
        done = terminated or truncated
    return episode

② Prediction: walk backwards, average

def mc_prediction(env, policy, episodes, gamma=1.0, first_visit=True, seed=0):
    V = defaultdict(float)                                    # unseen state → 0.0
    N = defaultdict(int)
    for _ in range(episodes):
        episode = play_episode(env, policy, rng)              # 1. play to the END
        first = first_visits([s for s, _, _ in episode])
        G = 0.0
        for t in reversed(range(len(episode))):           # 2. walk BACKWARDS
            s, a, r = episode[t]
            G = r + gamma * G                                 #    real return from step t
            if first_visit and first[s] != t:
                continue                                      #    count s once per game
            N[s] += 1
            V[s] += (G - V[s]) / N[s]                         # 3. the bandit's running mean
    return V, N
LineMeaning
defaultdict(float)Blackjack states are tuples like (13, 2, 1), so a dict is easier than a numpy array. A never-seen state reads as 0.0 (a placeholder, not knowledge).
play_episode(...)The whole game happens here. No table changes during the game.
reversed(range(...))The backwards walk. This is the line that makes it Monte Carlo.
G = r + gamma * GBefore this line, G is the return from step t+1; after it, from step t. Calculated from real rewards; nothing is read from V.
first[s] != tFirst-visit check: skip a state if it already appeared earlier in this game.
V[s] += (G - V[s]) / N[s]Updates the visited state s itself (not "the state you left" vs "landed": every visited state is updated once the game is over). Returns nothing; it changes the table.

③ Control: the same loop on Q, with ε-greedy play

def mc_control(env, episodes, eps=0.1, gamma=1.0, seed=0, exploring_starts=False):
    Q = defaultdict(lambda: np.zeros(2))                    # Q[s] = [Q(stick), Q(hit)]
    N = defaultdict(lambda: np.zeros(2))
    explore = epsilon_greedy_policy(Q, eps)                    # reads the LIVE Q every call
    for ep in range(episodes):
        episode = play_episode(env, explore, rng)               # 1. whole game, learn nothing
        first = first_visits([(s, a) for s, a, _ in episode])
        G = 0.0
        for t in reversed(range(len(episode))):              # 2. game over: walk backwards
            s, a, r = episode[t]
            G = r + gamma * G
            if first[(s, a)] != t:
                continue
            N[s][a] += 1
            Q[s][a] += (G - Q[s][a]) / N[s][a]                  # 3. average of real returns
    return Q, N, game_rewards

Compare with your Q-learning train(): the inner while loop and its update are replaced by "play the game, then a backwards for loop". There is no Q[s2] anywhere: MC never looks up the next state's value. And there is no policy-improvement line: because explore reads the current Q, the policy improves by itself after every game.

④ Testing

def win_draw_loss(env, policy, games=100_000, seed=12345):
    finals = np.array([sum(r for _, _, r in play_episode(env, policy, rng)) for _ in range(games)])
    return 100*np.mean(finals > 0), 100*np.mean(finals == 0), 100*np.mean(finals < 0), finals.mean()

The test uses greedy(Q) (always argmax, no ε) and does not learn. Same idea as evaluate() in project 3.

What to notice in the heatmaps

  • A cliff between 19 and 20. At 20 or 21 the policy sticks and usually wins (+0.6 to +0.9). At 12–19 it keeps hitting and usually busts: about −0.65 on average (no ace). The value surface is the policy's fingerprint.
  • A usable ace softens the blow (−0.2 to −0.5 instead of −0.65): the ace can switch from 11 to 1, so the next hit cannot bust you.
  • The dealer's ace column is the worst everywhere (20 vs A is only +0.14): a dealer showing an ace often makes 21.
  • Same states, two answers in Blackjack's case? No: first-visit and every-visit gave identical values (biggest difference 0.000000), because none of 100,000 games repeated a state.

12Off-policy: learning from others' games

Real output of python off_policy.py. Intuition only, with light maths.

The question: how good is the state (sum 13, dealer shows 2, usable ace) if I play "stick on 20+" (my target policy π)? But I have no games of my own. I only have games played by someone pressing random buttons (the behaviour policy b: hit or stick, 50/50).

The trick: re-weight each game

A random game that happens to look like something I would play is useful evidence. A game where the random player did something I would never do tells me nothing about my policy. The weight is called the importance-sampling ratio:

ρ  =  product over the moves of   π(a|s) / b(a|s)

    my policy would ALSO choose a:   π = 1,  b = 0.5   →  factor 1 / 0.5 = 2
    my policy would NEVER choose a:  π = 0             →  factor 0  (the whole game counts 0)

Five real random games

game 1: 13:hit, 13:hit        result G = −1   ρ = 2 × 2 = 4   (I'd hit too, both times)
game 2: 13:hit, 15:stick      result G = −1   ρ = 0           (I'd never stick on 15)
game 3: 13:stick              result G = +1   ρ = 0           (I'd never stick on 13)
game 4: 13:stick              result G = +1   ρ = 0
game 5: 13:stick              result G = −1   ρ = 0

Only game 1 looks like my policy, and it counts 4 times as much, because a random player follows my policy for two moves only 1 time in 4 (0.5 × 0.5).

Two ways to average

ordinary IS:   V = Σ ρ·G / (number of games)          unbiased, but can be wild
weighted IS:   V = Σ ρ·G / Σ ρ                        slightly biased, much calmer
Random games usedordinary IS errorweighted IS error
101.2090.540

10000.0140.015

True value (from playing "stick on 20+" itself 100,000 times): −0.281 (Sutton & Barto report −0.277). After 1,000 random games both estimates average about −0.26.

Connect it to Q-learning

Q-learning is also off-policy (it explores but learns about the greedy policy), yet it needs no ratios. Its target uses max Q[s2], a guess about what the greedy policy would do next, instead of the real rest of the game. Monte Carlo uses the real rest of the game, which was played by the explorer, so it must re-weight. That's one more reason TD-style methods became so popular.

13Real-world problems

Monte Carlo fits whenever the result only becomes clear at the end, and episodes really do end.

When to reach for Monte Carlo

✔ Episodes are fairly short and always finish. ✔ You can't trust step-by-step guesses (the state doesn't capture everything). ✔ You have a simulator you can run many times. ✘ Avoid it for never-ending tasks, or very long episodes where waiting is costly.

1 · A sales call script

Statestage of the call (greeting / needs / offer / objection), customer mood (estimated), offer already made?
Actionask a question / present offer A / present offer B / give a discount / end the call politely
Reward0 during the call; at the end: +profit if the customer buys, 0 if not; small −1 for very long calls
Episodeone call (a few minutes, always ends)
Why MCWhether a step was good is only known at the end (sale or not). The average of final results per (stage, action) is exactly what MC computes.
PitfallCustomers differ a lot: big variance, so you need many calls. You could use off-policy MC (importance sampling) to evaluate a new script from recorded calls made with the old script.

2 · Choosing a treatment plan in a simulated patient

Stateweek of treatment, measured symptoms band, side-effect level
Actioncontinue dose / increase / decrease / switch drug
Rewardat the end of the course: +10 if recovered, −10 if not, minus side-effect penalties
Episodeone full treatment course
Why MCOutcomes arrive at the end; researchers evaluate dosing rules in simulated patients first. MC evaluates a fixed rule by averaging outcomes, with no bootstrapped guesses about half-finished treatments.
PitfallNever learn by exploring on real patients. Real medical decisions need clinical trials and doctors. This is a "could be used for" in research simulations only.

3 · Game AI evaluated by self-play

Statethe board position
Actiona legal move
Reward+1 win, 0 draw, −1 loss, only at the end
Why MC"Play the game to the end many times and average the result" is exactly how Monte Carlo Tree Search judges positions, the planning method in booklet 08 (used in AlphaGo).

15Clearing up the confusions

Short, correct answers to common beginner questions.

Does Q-learning wait for the end and update backwards?

No. That's Monte Carlo. Q-learning updates after every step using its guess of the next state.

Why walk backwards? Couldn't we go forwards?

You could, but backwards is efficient: G at step t = rt+1 + γ·(G at step t+1). Walking backwards needs one multiply and one add per step.

Does Monte Carlo use the Bellman equation?

Not as an update rule. It never plugs in a guess of the next state. But the values it converges to do satisfy Bellman's equation, because they are the true averages.

How is this the same as my bandit's Q += (r − Q)/N?

It is the same incremental mean. In the bandit each "game" was one pull; here each (state, action) collects the returns G of the games that passed through it.

Why do we still need exploration?

If the agent never tries "hit on 13 vs dealer 2", it never gets a return for it and never learns its value. With ε = 0.01, 10 states never tried one action.

First-visit or every-visit: which is right?

Both converge to the true value. First-visit uses only the first time a state appears in a game; every-visit uses all of them. In Blackjack a state can't repeat (your sum only goes up, or the ace changes), so they're identical there.

Is Monte Carlo slower than TD?

Often, but not always. On Blackjack (1–3 moves per game) they're similar. On long games TD usually wins because its targets are less noisy (chapter 11).

What does "unbiased" mean here?

On average, the MC target equals the true value (0.502 vs 0.5). TD targets can be systematically off while the guesses are still wrong.

Can Monte Carlo work if the game never ends?

No. G is the total until the end. For never-ending tasks, use TD.

Why is the importance ratio 4 in game 1?

Two moves, each with π/b = 1/0.5 = 2. 2 × 2 = 4. A random player follows my policy twice in a row only 1 time in 4, so when it does, that game stands in for four.

Does the learned policy beat the casino?

No. Best learned average −0.040 per game: you still lose 4 paise per rupee bet on average. RL finds the best way to play; it can't change the game's odds.

Why do some learned chart cells look "wrong" compared to the textbook?

Near-ties. For (sum 12, dealer 2) Q(stick) = −0.300 vs Q(hit) = −0.301: a coin flip of noise decides the letter. More games shrink the noise.

Key formulas 
Return:   G_t = r_t+1 + γ·G_t+1
Average:  Q += (G − Q) / N
TD(0):    V += α(r + γV(s′) − V)
Ratio:    ρ = Π π(a|s) / b(a|s)
Ord. IS:  V = Σρ·G / n
Wtd. IS:  V = Σρ·G / Σρ
Four sentences to remember
  1. Monte Carlo plays the whole game, then walks backwards giving every visited (state, action) the real return G.
  2. Its value is just an average of returns, the same incremental mean as your bandit.
  3. No guesses means no bias, but one game's luck makes the target noisy; TD trades a little bias for much less noise.
  4. Learning from someone else's games needs importance-sampling weights ρ = Π π/b.
